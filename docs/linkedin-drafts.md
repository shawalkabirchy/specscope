## 1. Problem post

“Could we add a dashboard?” is a reasonable request.

It can also change the project you agreed to deliver.

Imagine an agency building a marketing website. The client asks for a dashboard to track inquiries. Before anyone starts work, both sides need to understand what that adds.

I’m building SpecScope as a self-initiated ConsoleLog Studio project to make that conversation clearer.

It puts the agreed deliverables beside the new request. The agency records its own scope decision and reasoning, then prepares an estimate and response.

The point is to make the next step explicit while the conversation is still easy to resolve.

If you run an agency or freelance practice, where do you currently keep these decisions?

## 2. Build-decision post

A quote should still mean the same thing after you change your hourly rate.

That shaped one of the main decisions in SpecScope.

Unpublished drafts use the current project rate. Publishing a quote freezes the request, scope revision, rate, fee, reasoning, and response.

If the request changes later, the app creates a linked draft. The original record stays intact.

The estimate is visible too: 20 minutes at 60.00/hour rounds upward to 30 billable minutes and a 30.00 additional fee.

This is a self-initiated ConsoleLog Studio portfolio project. The decisions are made by the agency user; the app does not interpret contracts automatically.

Small details like this can make a workflow easier to trust.

## 3. Demo / case-study post

One client request. One documented decision. One clear next step.

The SpecScope demo follows a fictional agency request from “Can we add an analytics dashboard?” to a published change order and a manually recorded approval.

The working flow includes:

- Comparing the request with a preserved scope revision.
- Recording a human scope decision and explanation.
- Calculating the additional fee with visible rounding.
- Editing a response in the agency’s own words.
- Preserving the quote and its decision history.

It runs locally in the browser. No account, email integration, or AI classification is required.

This is a self-initiated ConsoleLog Studio project, with synthetic data. It demonstrates the workflow rather than claiming customer results.
